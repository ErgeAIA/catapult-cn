# Catapult 完整参数配置指南

> 更新日期：2026-08-30
>
> 参数说明与推荐值已按 llama.cpp 官方文档对齐校正。

Catapult 是一个基于 Tauri 的 llama.cpp 桌面启动器，将 llama-server 的所有命令行参数封装成了可视化的图形界面。运行服务器页面共包含 **6 个配置选项卡**：上下文、硬件、采样、服务器、聊天、高级，外加仪表盘和模型的管理功能。下面逐一讲解。

***

## 模型管理

进入模型标签页后，主要功能分为三块：

- **下载目录**：新模型下载目录，例如 `D:\AI_Models`。
- **GGUF 存储目录**：在此添加本地目录，Catapult 会递归扫描其中所有 `.gguf` 文件并自动识别模型名称、参数量、上下文长度和视觉能力。
- **首选量化来源**：浏览 HuggingFace 时优先显示的量化来源列表。`unsloth` 排第一最实用，因为 Unsloth 的 UD-Q4\_K\_XL 量化在体积和准确率之间平衡最好。

***

## 运行时管理

- **托管运行时**：Catapult 从 GitHub Releases 下载并管理的 llama.cpp 版本，可以多版本共存、即时切换。
- **自定义运行时**：指向本地已有 llama.cpp 安装目录，例如你的 `D:\llama.cpp\llama-server.exe`。
- **可用后端**：系统检测到的计算后端，包括 CPU、CUDA（NVIDIA）、Vulkan（跨平台）、SYCL（Intel）、HIP（AMD）。推荐使用 CUDA（NVIDIA 用户）或 Metal（Mac 用户）。

***

## 上下文配置

这是影响模型行为和显存消耗的核心选项卡。

### 上下文与预测

**上下文大小**

- 含义：模型一次能"记住"的最大 token 数。token 约等于 0.75 个中文汉字。
- 设置建议：Qwen3.6-35B-A3B 原生支持 131072。设为 0 表示使用模型默认值。**推荐 32768**，兼顾长上下文能力和显存占用。32K ≈ 24000 汉字。
- 中配建议：8GB 显存设 **16384**；6GB 设 **8192**。

**批次大小**

- 含义：逻辑最大批次大小（提示处理的并行度），影响提示处理（prefill）速度。数值越大，处理长提示越快，但更耗显存。
- 默认值：2048。
- 推荐：保持默认。官方建议：纯 CPU / GPU 场景 512-2048，服务器并行请求场景 2048+。

**保留令牌**

- 含义：每次生成时保留初始提示的前 N 个 token，避免重复处理。0 = 不保留，-1 = 全部保留。
- 推荐：留空或设为 0，让模型自行管理。

**最大令牌数**

- 含义：单次生成的最大 token 数。-1 = 无限制。
- 推荐：**-1**，让 Claude Code 等客户端自行控制。

**微批次大小**

- 含义：物理最大批次大小，影响单次推理的显存峰值。
- 默认值：512，保持默认。

### 注意力与 KV 缓存

**Flash Attention**

- 含义：一种加速注意力计算的算法，能大幅降低显存占用和推理延迟。
- 设置建议：设为 **开启**。自动模式在某些场景下可能不会自动启用，显式开启更可靠。
- 注意：部分旧 GPU 不支持，但 RTX 30/40/50 系列完全兼容。

**KV 缓存类型 (K)** 和 **KV 缓存类型 (V)**

- 含义：Key 和 Value 缓存的精度类型。KV Cache 是 transformer 推理中存储中间结果的缓冲区，占用大量显存。
- 选项：`f32`、`f16`（16 位浮点，默认）、`bf16`、`q8_0`、`q4_0`、`q4_1`、`iq4_nl`、`q5_0`、`q5_1`。
- **重要**：Qwen3.5 系列在使用 f16 KV Cache 时准确率会下降（已有社区报告）。推荐统一设为 **q8\_0**，节省约 50% KV Cache 显存，且质量无明显损失。
- 中配建议：**q8\_0** 是最平衡的选择。若显存极紧张可尝试 `q4_0`，但质量有下降。

**SWA 完整**

- 含义：使用全尺寸滑动窗口注意力缓存。部分模型（如 Gemma、Mistral）原生使用滑动窗口。
- 推荐：**关闭（不勾选）**，除非你明确知道模型需要此功能。

**KV 卸载**

- 含义：将 KV Cache 卸载到 GPU 显存。默认开启。
- 推荐：**保持开启**。关闭后 KV Cache 走系统内存，速度会大幅下降。

**KV 统一**

- 含义：跨所有序列共享一个统一的 KV 缓冲区，而不是每个序列独立分配。可以减少显存碎片和总体占用。
- 说明：默认在并行槽数设为自动（-1）时启用。
- 推荐：**勾选开启**。对应命令行 `--kv-unified`。

**上下文移位**

- 含义：在无限文本生成中使用上下文偏移，当超出 context size 时自动丢弃旧 token 腾出空间。
- 推荐：保持默认（关闭）。Claude Code 等客户端会自行管理上下文。

**缓存提示**

- 含义：启用提示缓存，重复的提示前缀会被复用而不重新计算。默认开启。
- 推荐：**保持开启**，可以大幅加快连续交互的速度。

**缓存空闲槽**

- 含义：在执行新任务时保存并清除空闲槽位的 KV Cache。需要 KV 统一和缓存 RAM 配合使用。默认开启。
- 推荐：**保持开启**。

### 缓存复用

**缓存重用最小块**

- 含义：KV 移位重用的最小块大小，0 表示禁用。
- 推荐：保持默认（0）。高级用户可设为 8-32 以优化多轮对话的缓存利用。

### 缓存 RAM (MiB)

- 含义：KV Cache 可以占用的最大系统内存大小。-1 = 无限制，0 = 禁用，默认 8192（8GB）。
- 推荐：保持 **8192**，或者根据你的系统内存设为更大的值如 **16384**。

### 上下文检查点

**每个槽的最大检查点数**

- 含义：每个槽位最多保留多少个检查点，用于回退到之前的上下文状态。默认 32。
- 推荐：保持默认。

**检查点间隔**

- 含义：上下文检查点之间的最小间隔（token 数），0 = 无最小间隔，默认 8192。
- 推荐：保持默认。

## 硬件配置

### GPU

**GPU 层**

- 含义：将模型的多少层卸载到 GPU 上运行。可设具体层数，或用 `auto`（自动计算，默认）、`all`（-1 = 全部在 GPU）、0 = 全部在 CPU。
- **高配推荐（RTX 5080 16GB）**：设为 **-1（all）**，配合 `适配: 开启` 让 Catapult 自动管理。对于 35B MoE 模型，16GB 显存可能无法放下全部层，`适配` 会自动将溢出的层卸载到内存。
- **中配推荐（RTX 4060 8GB）**：设为 **-1** 并开启适配，或者手动设为 16-20 层。
- 注意：如果是纯 CPU 推理，设为 0。

**张量分割**

- 含义：多 GPU 时的张量分割比例，例如 `3,1` 表示第一张卡承担 3/4，第二张卡承担 1/4。
- 推荐：单卡用户留空。

**设备**

- 含义：指定用于卸载的设备索引，逗号分隔（如 `0,1`）。
- 推荐：单卡用户留空。

**适配目标 (MiB)**

- 含义：每张 GPU 保留的余量显存（MiB），防止显存占满导致 OOM。默认 1024（1GB）。
- 推荐：保持默认。

**分割模式**

- 含义：多 GPU 分割策略：None（不分）/ Layer（按层，默认，跨 GPU 流水线分载层与 KV）/ Row（按行，跨 GPU 并行分载权重）/ Tensor（按张量，并行，试验性）。
- 推荐：单卡用户保持默认 **Layer（默认）**。

**主 GPU**

- 含义：主 GPU 索引。
- 推荐：单卡留空（默认 0）。

**适配**

- 含义：自动调整参数以适应设备显存。如果模型超出显存，自动将部分层卸载到系统内存。
- 推荐：**开启**。这是 Catapult 最有用的功能之一，大大降低了手动调参的成本。
- 中配建议：**必须开启**，8GB 显存跑 35B MoE 需要靠此功能自动卸载。

**适配最小上下文**

- 含义：适配模式下的最小上下文大小，默认 4096。
- 推荐：保持默认。

### CPU

**线程数**

- 含义：CPU 生成线程数。-1 = 自动。
- 官方建议：纯 CPU 推理用**物理核心数**（非超线程数）；有 GPU 时 **4-8 线程**即可（线程过多反而变慢）；服务器并行场景每请求 **2-4 线程**。
- 推荐：**留空（自动）**。llama.cpp 会自动选择合适数量。

**批次线程数**

- 含义：批处理（提示处理）时的 CPU 线程数。默认与线程数相同。
- 官方建议：提示处理与自回归生成可分离，提示处理线程可以设得更高以加速 prefill（例如线程 4 / 批次线程 8）。
- 推荐：留空。

**NUMA**

- 含义：非统一内存访问优化，用于多路 CPU 服务器。类型：distribute（运算均匀分布到所有节点）/ isolate（仅在与执行起点同节点的 CPU 上建线程）/ numactl（使用 numactl 提供的 CPU 映射）。
- 推荐：**禁用**。消费级桌面平台不需要。

### 内存管理

这部分控制模型权重和 MoE 专家的内存布局策略，对显存有限的场景影响很大。

> 新版已统一为 **加载模式（--load-mode）** 管理模型加载方式，旧的 mlock / 内存映射 / 直接 IO 三个开关均已标记为 DEPRECATED，优先建议使用加载模式。

**加载模式**

- 含义：统一控制模型如何加载到内存。选项：`auto`（默认，自动 mmap，除非设备不支持）/ `none`（无特殊模式）/ `mmap`（内存映射）/ `mlock`（锁定到物理内存，防止交换）/ `mmap+mlock`（两者结合）/ `dio`（使用 DirectIO）。
- 推荐：保持 **auto**。下方三个旧开关仅在需要精细控制时使用。

**mlock**

- 含义：将模型权重锁定在系统物理内存中，禁止交换到磁盘。防止因内存交换导致的推理延迟抖动。
- 推荐：**开启**。如果你有足够的系统内存（32GB+），开启后推理延迟更稳定。系统内存紧张时关闭。
- 中配建议（8-12GB 显存 + 16GB 内存）：**关闭**，因为你的系统内存本身就不宽裕。

**内存映射**

- 含义：将模型文件通过内存映射加载，而不是一次性全部读入内存。默认开启。
- 推荐：**保持开启**。开启后模型加载更快，且操作系统可以按需分页加载权重。

**直接 IO**

- 含义：如果操作系统支持，使用 DirectIO 绕过文件系统缓存直接读取磁盘。
- 推荐：**关闭**。桌面平台通常不需要，且可能会与 Memory Map 冲突。

**CPU MoE**

- 含义：将所有 MoE 专家的权重强制保留在 CPU 内存中，不卸载到 GPU。对于 MoE 模型（如 Qwen3.6-35B-A3B），专家层占用了大部分参数量。
- 推荐：**关闭**。关闭后 Fit 会自动决定哪些层放在 GPU、哪些放在 CPU。如果显存非常紧张（6-8GB），可以开启此项强制所有专家放在 CPU，这样 GPU 只负责 attention 层，显存占用骤降，但推理速度会大幅下降。
- 中配建议（6-8GB）：**开启**。牺牲速度换取稳定性，确保不 OOM。

**CPU MoE（草稿）**

- 含义：对草稿模型的 MoE 权重的相同策略。
- 推荐：**关闭**（通常不用草稿模型）。

**权重重打包**

- 含义：启用权重重新打包，优化权重在内存中的布局以提高缓存命中率。默认开启。
- 推荐：**保持开启**。

**算子卸载**

- 含义：将主机侧的张量操作（如 reshape、permute）卸载到设备（GPU）上执行。默认开启。
- 推荐：**保持开启**。减少 CPU-GPU 同步开销。

**无主机缓冲区**

- 含义：绕过主机缓冲区，为设备缓冲区直接申请额外显存。
- 推荐：**关闭**。开启后可能在某些显卡上提高性能，但也可能导致兼容性问题。

**检查张量**

- 含义：在加载模型时验证张量数据的完整性，确保 GGUF 文件没有损坏。
- 推荐：**开启（推荐）​**。首次加载模型或下载新模型后开启一次确认无误，之后再关闭以节省启动时间。

**N 个 CPU MoE 层**

- 含义：指定有多少层 MoE 权重保留在 CPU 上。优先级高于 CPU MOE 开关——设了具体层数则 CPU MOE 开关不再生效。
- 推荐：**留空**。让 CPU MOE 总开关统一控制。

**N 个 CPU MoE 层（草稿）**

- 含义：同上，针对草稿模型。
- 推荐：留空。

### 覆盖

用于高级调试和特殊场景，可以覆盖模型的内部张量分配和配置参数。

**覆盖张量**

- 含义：覆盖指定张量的设备分配。格式：`<pattern>=<buffer type>,...`
- 示例：`attn_v=cuda0` 将 attention 的 V 矩阵强制分配到第一张 GPU。
- 推荐：**留空**。只有多卡用户需要精细控制张量分配时才用。

**覆盖张量（草稿）**

- 含义：同上，针对草稿模型。
- 推荐：留空。

**覆盖 KV**

- 含义：覆盖模型配置中的键值对。格式：`KEY=TYPE:VALUE,...`
- 示例：`tokenizer.ggml.add_bos_token=bool:false` 强制关闭 BOS token。
- 推荐：**留空**。用于调试或绕过模型文件中的错误配置。

## 采样配置

采样参数控制模型生成文本时的"创造力"和随机性。

### 基础

**温度**

- 含义：温度参数。值越高生成越随机、有创意；值越低越确定、保守。
- 范围：0.0 - 2.0+
- 推荐（思考模式）：**0.60**（Qwen 官方推荐）。日常聊天可设 0.7-0.8。
- 纯编码任务：可降至 **0.3-0.4** 以获得更确定性输出。
- 中配建议：参数本身不消耗显存，以上数值通用。

**随机种子**

- 含义：随机种子。-1 = 完全随机。设固定值（如 42）可复现生成结果。
- 推荐：**-1**。

**采样器**

- 含义：采样器链，定义了采样器的执行顺序。
- 默认值：`penalties;dry;top_n_sigma;top_k;typ_p;top_p;min_p;xtc;temperature`
- 推荐：**保持默认**，这是 llama.cpp 开发者优化过的顺序。

### 核采样 / Top-K / Min-P

**Top-K**

- 含义：只从概率最高的 K 个 token 中采样。设为 40 意味着模型只能在 Top 40 个备选 token 中选择。
- 推荐：**40**（默认值）。
- 编码任务：可降至 **20-30**。

**Top-P**

- 含义：累积概率阈值（核采样）。从概率累积到 P 值的 token 集合中采样。
- 推荐：**0.95**（Qwen 官方推荐）。

**Min-P**

- 含义：相对于最高概率 token 的最低概率阈值。例如 0.05 意味着只有概率不低于最高 token 5% 的 token 才被考虑。
- 推荐：**0.05**（Qwen 官方推荐）。
- 作用：自动过滤掉极低概率的"垃圾"token，比 Top-K 更优雅。

### Top-N-Sigma

- 含义：基于标准差的动态 Top-K 替代方案。-1 = 禁用。
- 推荐：**-1（禁用）**。

### Typical P

- 含义：典型采样，选择与预期分布最接近的 token。1.0 = 禁用。
- 推荐：**1.0（禁用）**，与 Top-P/Min-P 功能重叠。

### 惩罚

**重复最后 N**

- 含义：在最后 N 个 token 范围内检测重复并施加惩罚。0 = 禁用，-1 = 整个上下文。默认 64。
- 推荐：**0（禁用）**，交给客户端控制。若模型出现严重重复，可设为 512-1024。

**重复惩罚**

- 含义：重复 token 的惩罚系数。1.0 = 禁用。
- 推荐：**1.0（禁用）**。Claude Code 等客户端会自行控制。

**存在惩罚**

- 含义：对已出现过的 token 施加固定惩罚，鼓励模型谈论新话题。0.0 = 禁用。
- 推荐：**0.0（禁用）**。

**频率惩罚**

- 含义：对频繁出现的 token 按出现次数追加惩罚。0.0 = 禁用。
- 推荐：**0.0（禁用）**。

### XTC（排他性 Top-p 链）

**XTC 概率**

- 含义：XTC 采样概率。0.0 = 禁用。
- 推荐：**0.0（禁用）**。这是一个较新的实验性采样器，社区反馈不一，暂不建议启用。

**XTC 阈值**

- 含义：XTC 阈值，默认 0.10。
- 推荐：保持默认（仅当启用 XTC 时有用）。

### DRY 采样（重复抑制采样）

- 一种基于行级的重复检测和惩罚机制。
- **DRY 倍数**：0.0 = 禁用（默认）。
- **DRY 基数**：默认 1.75。
- **DRY 允许长度**：允许的重复行最大长度，默认 2。
- **DRY 惩罚最后 N**：作用于最后 N 个 token，默认 64，0 = 禁用。
- 推荐：全部保持 **默认（禁用）**。

### 自适应采样

**自适应目标**

- 含义：自适应采样（adaptive-p）的目标概率，选择概率接近该值的 token。有效范围 0.0~1.0；**负数 = 禁用**，默认 -1。
- 推荐：保持 **-1（禁用）**。

**自适应衰减**

- 含义：目标概率的衰减率。值越低反应越快，越高越稳定。有效范围 0.0~0.99，默认 0.90。
- 推荐：保持默认（仅当启用时有用）。

### 动态温度

**范围**

- 含义：温度动态调整的波动范围。例如温度为 0.6、范围为 0.3，则温度在 0.45-0.75 间动态变化。
- 推荐：**0.0（禁用）**。

**指数**

- 含义：动态温度的指数曲线参数。
- 推荐：保持默认。

### MIROSTAT

## 服务器配置

### 网络

**主机地址**

- 含义：服务器监听的 IP 地址。

**端口**

- 含义：服务器端口号。
- 默认：8080。
- 推荐：**8001**。如果被占用可改为 8080、8081 等。

**并行槽**

- 含义：并行处理的请求槽位数。-1 = 自动。
- 推荐：**1**。本地使用不需要多槽位。多用户场景可设为 2-4。

**HTTP 线程**

- 含义：HTTP 服务器线程数。-1 = 自动。
- 推荐：留空（自动）。

**超时（秒）**

- 含义：读写超时时间（秒）。新版默认 3600（1 小时），旧版为 600（10 分钟）。
- 推荐：保持默认。长上下文生成可能需要更长时间，可设为 1800-3600。

**SSE 心跳间隔**

- 含义：SSE（流式输出）心跳包发送间隔（秒），-1 = 禁用，默认 30。
- 推荐：保持默认。

**端口复用**

- 含义：允许同一端口被多个 socket 绑定（reuse-port）。默认禁用。

**空闲休眠（秒）**

- 含义：空闲 N 秒后自动休眠。-1 = 禁用。
- 推荐：**-1（禁用）**。本地使用不需要自动休眠。

**API 密钥**

- 含义：访问 API 所需的密钥，逗号分隔可设置多个。

**API 密钥文件**

**API 前缀**

- 含义：URL 前缀，不带尾部斜杠。

# Catapult 按显存分级推荐配置速查（完整版）

以下配置针对 **Qwen3.6-35B-A3B（UD-Q4\_K\_M 量化）​** 编写。该模型为 35B MoE（每 token 激活 \~3B），GGUF 文件约 20-22GB。在任何单卡上都无法将完整模型权重全部装入显存，全靠 **Fit 自动卸载**将放不下的层调度到系统内存。

## 二、各显存级别详解

### 6GB — 入门级

*代表显卡：RTX 3050、RTX 2060、GTX 1660 Super*

只能将少量层卸载到 GPU，大部分推理在 CPU 上完成。上下文限制在 4096，适合基础对话和简单代码补全。

关键设置说明：

- **CPU MOE：开启**。强制所有 MoE 专家留在 CPU，GPU 只负责 attention 层，大幅降低显存占用。
- **mlock：关闭**。系统内存仅 16GB 的情况下锁定权重可能导致整体卡顿。
- **Fit Target：256 MiB**，极限利用显存余量。
- Continuous Batching 关闭，Parallel Slots 为 1。

如果使用体验不理想，建议考虑 Qwen3.5-9B 或 Qwen3.5-4B，会更顺畅。

### 8GB — 中低配

*代表显卡：RTX 4060、RTX 3070、RTX 2070 Super*

约 12-16 层可卸载到 GPU，日常编码和对话可用。上下文 8192。

关键设置说明：

- **CPU MOE：建议开启**。8GB 显存对于 35B MoE 仍然紧张，开启后虽然牺牲速度但确保不 OOM。
- **mlock：关闭**。
- **关闭 Continuous Batching**，避免多请求争抢显存。
- 如果你愿意牺牲一些上下文长度换取速度，可以将 Context Size 降到 4096 并关闭 CPU MOE，让 GPU 多承担一些工作。

### 12GB — 中高配

*代表显卡：RTX 4070、RTX 3080、RTX 4060 Ti 16GB（可用 16GB 配置）*

甜点级别。约 20-26 层在 GPU 上跑，上下文 16384。

关键设置说明：

- **CPU MOE：关闭**。12GB 已经不需要强制专家留在 CPU 了，让 Fit 自动管理即可。
- **mlock：关闭**。如果你的系统内存有 32GB 可以开启。
- 可以开启 Continuous Batching 了。
- 使用体验已经很流畅，日常使用几乎感觉不到 CPU 参与。

### 16GB — 高配

*代表显卡：RTX 5080、RTX 4080 Super、RTX 4070 Ti Super*

约 28-36 层在 GPU 上跑，大部分生成和提示处理都在 GPU 内完成。上下文 32768。

关键设置说明：

- **CPU MOE：关闭**。
- **mlock：开启**。如果系统内存 32GB+，开启后延迟更稳定。
- 35 t/s 以上的速度，Claude Code 体验接近云端 API。
- 这是当前性价比最高的甜点选择。

### 24GB — 顶配

*代表显卡：RTX 5090、RTX 4090、RTX 5090D*

约 45-55 层可卸载到 GPU——模型的大部分层都在显存里。

关键设置说明：

- **CPU MOE：关闭**，让 Fit 全权决定。
- **mlock：开启**。
- **KV Cache 用 bf16 全精度**，不牺牲任何质量。
- **Context Size 开到 65536\~131072**。
- **Parallel Slots 可开 2-4**，同时服务多个会话。
- 配合 5090 的 1.8 TB/s GDDR7 带宽，推理速度可达 50-70 t/s。

## 四、参数设置原则总结

**1. GPU Layers 永远用 -1**
-1 + Fit On 的组合让 Catapult 自动计算最佳分配策略。

**2. CPU MOE 是显存不足时的救命稻草**
6-8GB 显存必须开启，12GB 以上建议关闭。这是 MoE 模型独有的优化手段——把占大头的专家层留在 CPU，GPU 只跑 attention。

**3. KV Cache 精度 = 显存余额的风向标**
24GB 用 bf16，12-16GB 用 q8\_0，8GB 以下 q8\_0 是底线。**不要使用 f16**，Qwen3.5 系列在 f16 KV Cache 下准确率有已知问题。

**4. Context Size 由 KV Cache 显存决定**
Q4\_K\_M + q8\_0 KV Cache 下，每 8K 上下文约消耗 0.8-1.2GB 显存。用这个比例估算再下调 25% 留出余量。

**5. mlock 在系统内存充足时开启**
32GB+ 系统内存可以安心开启，16GB 建议关闭防止内存压力。

**6. Sampling 参数优先沿用官方推荐**
0.60 温度 + 0.95 Top-P + 0.05 Min-P + 40 Top-K 是最稳定的起点。

**7. 量化优先 Q4\_K\_M / Q5\_K\_M**
官方性能指南将 Q4\_K\_M 或 Q5\_K\_M 视为速度/质量的最佳平衡点；Q6\_K 接近原版质量、Q8\_0 仅作参考/评测。

**8. 线程数按场景设置，不是越多越好**
纯 CPU = 物理核心数；有 GPU = 4-8 线程；服务器并行 = 每请求 2-4 线程。线程过多反而变慢。

**9. 服务器并行时 batch-size 要足够大**
官方建议批大小需满足 `batch-size ≥ ctx-size × 并行槽数`，否则连续批处理场景中后续请求会等待。
